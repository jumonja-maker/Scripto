# ScriptoLib — проверка плеера перед M2

Дата: 26 октября 2026 года. Статус: план проверки, движок ещё не подключён и не утверждён.

Первым кандидатом предлагается **libmpv**. Его официальный API предназначен для встраивания воспроизведения в другое приложение. Это позволяет оставить собственную небольшую панель управления ScriptoLib. Подгонка на первом этапе означает настройку интеграции и интерфейса; изменять исходники декодеров без подтверждённой причины не планируется.

| Кандидат | Основание для рассмотрения | Что нужно подтвердить в ScriptoLib |
|---|---|---|
| libmpv | API для встроенного аудио/видео, управление состоянием, дорожками и субтитрами; настройки аппаратного декодирования | Встраивание в Qt Quick, корректное закрытие, стабильность Windows-сборки и фактический GPU-путь |
| libVLC | Встраиваемый движок VLC с API медиаплеера, звуковых дорожек и субтитров | Те же реальные файлы, работа в выбранной оболочке, поставка необходимых модулей |

Это инженерный выбор кандидатов, а не результат сравнительного теста. libVLC рассматриваем, если проверка libmpv выявит существенную проблему. В первую поставку не добавляем оба движка одновременно.

Источники: [официальное руководство mpv, встраивание через libmpv](https://mpv.io/manual/stable/#embedding-into-other-programs-libmpv), [API libVLC](https://github.com/videolan/vlc-3.0/blob/master/include/vlc/libvlc_media_player.h), [описание проекта VideoLAN](https://github.com/videolan/vlc).

## Как принимаем M2

Проверка выполняется на Windows 11, в том числе на доступном устройстве с AMD Radeon. Перед тестом записываем фактически используемый GPU, версию драйвера, версию движка и параметры сборки. Наличие аппаратного декодирования в документации не подтверждает его работу в приложении: режим зависит от связки рендерера, драйвера и формата. [Документация mpv по аппаратному декодированию](https://mpv.io/manual/stable/#options-hwdec).

Небольшой набор настоящих файлов пользователя дополняется техническими образцами там, где нужного случая нет. Для каждого файла записываем контейнер, видео- и аудиокодек, разрешение, кадровую частоту и результат. Само расширение файла не определяет кодек.

| Сценарий | Что фиксируем |
|---|---|
| MP4 и MKV, H.264 и HEVC, доступные 1080p/4K образцы | Появление изображения, звук, пропущенные кадры, фактический режим декодирования |
| Один обычный фильм в течение 30 минут | Устойчивость звука и изображения, отсутствие накопления памяти и зависаний |
| Несколько открытий, пауз, остановок и закрытий | Завершение плеера, отсутствие оставшегося звука и зависших процессов |
| Имя и путь с кириллицей и пробелами | Открытие именно выбранного файла |
| Отсутствующий, пустой или повреждённый файл | Понятная ошибка; следующий исправный файл продолжает открываться |
| Запуск без сети | Локальное воспроизведение не ждёт подключения и авторизации |
| Программное декодирование после недоступного аппаратного | Понятное поведение и измеренная пригодность для конкретного файла |

Для тяжёлых 4K/HEVC и других вариантов результат записывается отдельно. Не обещаем одинаковую плавность для всех кодеков на любом оборудовании. HDR и AV1 добавляются к заявленным возможностям только после отдельного подтверждения на соответствующих файлах и экране.

Сравнение с самостоятельным mpv той же версии поможет отличить проблему самого файла от ошибки встраивания. К M2 предъявляются требования запуска, паузы, остановки, громкости, корректного закрытия и стабильного воспроизведения. Перемотка, восстановление позиции, переключение дорожек и субтитры принимаются следующими отдельными шагами RoadMap.

## Поставка

До включения бинарного движка в сборку закрепить его источник, версию, контрольную сумму и лицензии компонентов. У mpv варианты GPL/LGPL зависят от конкретной сборки и зависимостей; бесплатное распространение ScriptoLib не заменяет выполнение этих условий. Перечень уведомлений и необходимых исходников определяется по фактически выбранным бинарным файлам. В M1 бинарного медиадвижка нет. Основание: [mpv Copyright](https://github.com/mpv-player/mpv/blob/master/Copyright).

Решение после испытаний: принять libmpv, исправить конкретную проблему интеграции или провести тот же набор на libVLC. Пока результаты Windows-тестов отсутствуют, статус остаётся «кандидат».
